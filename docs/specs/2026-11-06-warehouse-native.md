# 数仓直连改造规格

## 目标

连上零售数仓，选择门店、品类、周次后，从明细表当场算出指标，生成与原周报同结构的诊断报告（HTML/PDF）。提供 Streamlit 页面和命令行两个入口。

## 范围

- 一份 `semantic.yaml` 描述表和字段。销售事实表必填；目标、客流、商品、门店、库存可选，未配置的指标不显示。
- 用 SQLAlchemy Core 生成条件聚合 SQL 并下推到数仓，查询值全部参数绑定。
- 对比期：本周、滚动 4 周、财年累计，以及各自的去年同期（默认平移 364 天，对齐星期）。
- 对标：同组其他门店的合计指数、排名、与前一名的差距。
- 分析：渠道 → 销售树（附对数贡献分解）→ 子类 → 系列 → 商品下钻，保留原 notebook 的贡献度截断与潜力规则。
- 文字：模型 通过 OpenAI 兼容接口生成，只负责组织语言。出现事实里没有的数字、方向说反或命中禁用词时，该段退回规则模板。
- 周数据不完整或门店无数据时明确报错，不产出残缺报告。

## 不做

- SHAP 归因与销量预测：现有实现存在目标泄漏，原 PDF 也未使用。销售树分解和贡献度下钻已能回答涨跌原因。
- 线上加购、结算等多级漏斗：客流表可覆盖 PIP 到成交，更细的步骤等有真实需求再加。
- 账号体系、IM 推送、自定义财年周历。

## 验收

- 小型手算数据：SQL 结果与手算指数完全一致。
- 演示数仓：Sales = Tickets × ATV 等恒等式成立，报告找出预埋的上升和下降异动。
- SQLite 上完整跑通，并能编译到 Postgres、MySQL、MaxCompute 方言。
- 命令行和页面都能生成报告，HTML、PDF 人工查看无误。模型 真实调用一次。
- MaxCompute、Postgres、MySQL 未做真实联调，需要在真实环境执行 `reportagent check`。
